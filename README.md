✅ Hub 클러스터

중앙 통제 두뇌 역할(계산 + 관리 역할)

다른 클러스터들의 CPU 사용량, 메모리 여유, 탄소 강도(carbon intensity), Prometheus 지표 등을 수집(FAST api 사용)

그 데이터를 기반으로 최적화 수식(MILP) 을 계산해
→ “어느 클러스터에서, 언제, 어떤 작업을 실행할지” 결정

한번만 계산 X, 주기적으로 전체 상태 최적화

✅ 다수의 워커(Region) 클러스터들

실제 작업(Job)을 수행하는 곳

Hub는 각 클러스터의 kubecontext를 알고 있어서
kubectl --context k3d-kr apply ... 이런 식으로 원격으로 Job을 배포함

✅ 작업 큐 (Job Queue)

새로 들어온 작업을 잠시 보관하는 대기열

Hub가 주기적으로 이 큐를 확인하고,
최적화 수식을 다시 계산해서 “지금 실행할 잡”을 결정함

✅ 탄소 최소화 수식 (목표함수)

각 클러스터의 탄소강도, CPU 사용량, 마감(deadline), 데이터 이동비용을 고려해
전체 CO₂ 배출량을 최소화하도록 계획을 세움.

프로메테우스를 사용하면 실시간 CPU/메모리 사용량을 모니터링 가능

MCAD를 사용하면 단일 JOB이 아닌 JOB 그룹 단위로 스케줄링 가능

Dry-Run 모드
실제 JOB을 클러스터에 적용하지 않고, 계산만 해보고 어디가 최적인지 log에 출력

시간을 슬롯으로 나눔
연속적인 시간이 아니라 슬롯 단위로 JOB 계획

데이터 이동 비용
멀리 있는 클러스터로 이동할때 전송 전력 탄소량 추가(데이터크기(data_gb)와 네트워크 탄소 계수(net_intensity)를 곱한 보조 패널티 항)

실행중이던 작업 이동이 아니라 다음 JOB을 실행할 클러스터를 결정

PuLP라는 선형계획 라이브러리 사용해서 탄소 최적 계산

제약 조건
한 클러스터에는 하나의 작업, 클러스터 별 CPU 용량 제한, 각 job은 정해진 시간만큼 실행, deadline 이후로는 실행 X
